# Agent 컨텍스트 유지관리

## 분류 기준

- 파일 탐색이나 기존 코드 확인으로 알 수 있는 정보는 상시 지침에 넣지 않는다.
- 지시가 없을 때 Agent가 반복적으로 반대로 행동하는 항목은 상시 지침 후보로 삼는다.
- 팀이나 저장소마다 선택이 달라지는 중요한 판단은 이 저장소의 결정을 짧게 명시한다.
- 보안·라이선스처럼 한 번의 누락도 위험한 금지사항은 반복 횟수와 관계없이 항상 적용한다.
- 일회성 요구, 배경 설명, 전체 명령 목록은 규칙으로 승격하지 않는다.

## 변경 절차

1. 수동으로 고친 사례와 막으려는 실패 유형을 기록한다.
2. 기존 규칙이나 참조 문서로 이미 해결되는지 확인한다.
3. 모든 작업에 필요한 판단이면 `AGENTS.md`에 한 행동만 지시하는 문장으로 추가한다.
4. 특정 단계에만 필요하면 정본 문서에 두고 `INDEX.md`에서 조건과 완료 결과만 연결한다.
5. 중복되거나 탐색으로 대체할 수 있는 규칙은 합치거나 삭제한다.

[출처를 기록한 참고 글](../../THIRD_PARTY_NOTICES.md)의 8가지 구현 원칙은 이 저장소의 구현 기준선으로 취급한다. 프로젝트 성격이 달라져 예외가 필요하면 원칙을 조용히 약화하지 말고 적용 범위와 이유를 명시적으로 갱신한다.

분기마다 상시 지침을 다시 읽고 반복 실패를 막지 못하는 문장, 더 이상 유효하지 않은 선택, 상세 절차로 비대해진 항목을 제거하거나 인덱스로 내린다.
