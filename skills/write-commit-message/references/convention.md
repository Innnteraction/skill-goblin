# 기본 커밋 메시지 컨벤션

대상 프로젝트가 정하지 않은 항목에만 이 규칙을 적용한다.

## 제목

```text
<type>[(scope)]: <summary>
```

- `scope`는 프로젝트가 허용하고 변경 영역을 구분하는 데 도움이 될 때만 사용한다.
- `summary`는 변경 결과를 프로젝트의 주 언어로 간결하게 설명한다. 주 언어를 알 수 없으면 사용자의 언어를 사용한다.
- 제목은 한 줄로 쓰고 마침표로 끝내지 않는다. 대상과 결과가 드러나지 않는 `수정`, `업데이트`, `작업` 같은 표현만 사용하지 않는다.
- 영어는 명령형 현재 시제, 한국어는 결과가 분명한 표현을 사용한다.

## 타입

표준 타입은 일반적인 Conventional Commits 의미로 `feat`, `fix`, `docs`, `refactor`, `test`, `build`, `ci`, `perf`, `style`, `revert`, `chore`를 사용한다. 다음 타입을 비개발 작업에 추가한다.

| 타입 | 사용 기준 |
| --- | --- |
| `plan` | 계획, 로드맵, 요구사항 또는 실행 기준을 변경한다. |
| `research` | 조사 결과, 실험 기록 또는 분석을 변경한다. |
| `design` | UX·UI·시스템 설계안이나 디자인 산출물을 변경한다. |
| `content` | 제품 문서가 아닌 사용자 대상 문안, 미디어 또는 편집 콘텐츠를 변경한다. |

- 의사결정 기준을 세우면 `plan`, 결정된 사용법을 설명하면 `docs`를 사용한다.
- 설계 선택과 구조를 정의하면 `design`, 사용자에게 노출되는 문안 자체를 만들면 `content`를 사용한다.
- 사용자 역량을 추가하면 `feat`, 저장소를 유지관리할 뿐이면 `chore`를 사용한다.

## 본문

제목만으로 맥락과 접근법을 이해하기 어려울 때 필요한 섹션을 작성한다.

```text
Why
변경 배경이나 선택 근거

What
달라진 동작, 문서, 결정 또는 결과

How
구현·작성 접근법과 필요한 사용·검증 방법
```

반복하거나 추측해야 하는 섹션은 생략한다. 자명한 오탈자나 기계적 변경은 본문 전체를 생략할 수 있다.

## Footer와 Agent 표기

- 프로젝트가 요구하는 footer를 먼저 기록한다.
- Agent가 메시지를 생성하거나 실질적으로 초안을 작성했으면 메시지 마지막에 `Agent: <vendor> <model>`을 둔다.
- 현재 실행 중인 Agent의 vendor와 model이 모두 확인될 때만 trailer를 기록한다. 어느 하나라도 확인할 수 없거나 명시된 정보끼리 충돌하면 trailer 전체를 생략한다.
- 식별자는 확인한 표기 그대로 사용하며 축약하거나 일반화하지 않는다.
- Agent가 사람의 메시지를 변경하지 않고 검토만 했다면 trailer를 추가하지 않는다.
- `Agent:` 뒤에는 다른 내용을 추가하지 않는다.

### 식별자 판정

| 근거 | 판정 |
| --- | --- |
| 시스템 또는 실행 환경이 현재 실행 중인 Agent라고 명시한 vendor와 model | 사용한다. |
| 직접 확인할 수 있는 UI가 현재 선택되어 실행 중인 vendor와 model을 명시한 경우 | 사용한다. |
| `GPT-5 기반` 같은 모델 계열·기반 설명 | 정확한 model로 간주하지 않는다. |
| `Codex`, `Claude Code` 같은 제품·실행 화면 이름 | vendor나 model로 간주하지 않는다. |
| 선택할 수 있는 모델 목록 | 현재 실행 중인 model의 근거로 사용하지 않는다. |
| 환경 변수 이름, 과거 커밋의 trailer, 저장소 기본값 | 현재 실행 중인 식별자로 추정하지 않는다. |

여러 신뢰 가능한 근거가 서로 다르면 하나를 임의로 선택하지 않는다. 확인할 수 없는 경우와 마찬가지로 trailer를 생략한다. 메시지를 커밋했다면 최종 보고에서 정확한 식별자를 확인하지 못해 trailer를 생략했다고 알린다.

## 예시

```text
plan(release): 분기 배포 승인 기준 정리

Why
담당자마다 배포 가능 여부를 다르게 판단하고 있었다.

What
필수 검사, 승인 주체, 중단 조건을 하나의 계획으로 정리한다.

Agent: OpenAI gpt-5.6-sol
```

```text
docs: README 링크 오탈자 수정
```

두 번째 예시는 정확한 vendor와 model을 모두 확인하지 못했거나, 사람이 작성한 메시지를 변경 없이 검토한 경우다.
