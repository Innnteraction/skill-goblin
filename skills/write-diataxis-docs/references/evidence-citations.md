# 근거 인용 가이드

독자가 본문의 설명에 집중하도록 긴 파일 경로와 출처 설명을 짧은 번호 인용 뒤로 옮긴다. 번호는 읽기 순서를 위한 표시이고, `cite-` 키는 출처를 추적하는 안정적인 식별자다.

## 적용 여부

먼저 대상 프로젝트의 Markdown renderer, 문서 내비게이션, 합본 순서와 기존 인용 관례를 확인한다.

- Pandoc, Quarto, LaTeX나 문서 사이트가 안정적인 인용 키와 숫자 스타일을 이미 지원하면 그 형식과 빌드 검증을 사용한다.
- 별도 관례가 없고 한 Markdown을 독립적으로 읽으면 문서 내부 번호를 사용한다.
- 여러 Markdown을 각각 열어도 같은 출처가 같은 번호여야 하면 중앙 근거 문서를 사용한다.
- 여러 파일이 하나의 산출물로만 읽히면 기존 renderer가 합본 전체의 번호를 계산하게 한다. 원본 파일의 로컬 번호까지 억지로 일치시키지 않는다.

일반 탐색이나 다음 절차로 이동시키는 링크는 의미 있는 링크명을 본문에 유지한다. 사실을 뒷받침하는 코드, 설정, 스키마, 테스트, 실행 결과, 공식 제품 문서와 외부 1차 자료만 번호 인용으로 바꾼다. 모든 문장에 인용을 붙이지 말고 독자가 하나의 주장으로 이해하는 문장이나 문단 뒤에 둔다.

## 단일 문서

본문에는 표시 번호와 안정 키를 함께 가진 로컬 링크를 쓴다.

```markdown
재시도 요청은 처음 받은 멱등성 키를 유지한다.[[1]](#cite-retry-idempotency)

## 근거

1. <a name="cite-retry-idempotency"></a> **재시도 키 유지.** [`src/orders/retry.ts`의 `retryOrder`](../src/orders/retry.ts)와 관련 테스트를 확인했다. 검증 revision: `abc1234`.
```

`cite-<semantic-slug>` 키는 번호, 파일명이나 줄 번호가 아니라 근거가 지지하는 의미를 나타낸다. 같은 근거를 다시 인용하면 같은 키와 번호를 재사용한다. 서로 무관한 출처를 한 번호에 합치지 않고, 한 주장을 여러 출처가 함께 지지하면 번호 인용을 나란히 둔다.

근거 항목은 최초 등장순으로 `1`부터 연속해서 배치한다. 항목에는 독자가 출처를 판별하는 데 필요한 짧은 설명과 locator만 둔다. 내부 분석 명령, 원시 claim 표와 독자에게 필요 없는 추적 메타데이터는 옮기지 않는다.

## 여러 문서의 전역 번호

문서 묶음의 마지막에 기본 이름 `references.md`인 중앙 근거 문서를 둔다. 기존 내비게이션이나 합본 설정에서 문서 순서를 확인하고, 없으면 사용자에게 순서를 확인한다. 번호는 지정된 순서에서 각 키가 처음 등장한 순서로 계산한다.

```markdown
<!-- chapters/operations.md -->
재처리 전에 현재 상태를 다시 읽는다.[[1]](../references.md#cite-retry-state-check)
```

```markdown
<!-- references.md -->
# 근거

1. <a name="cite-retry-state-check"></a> **재처리 전 상태 확인.** [`src/orders/retry.ts`의 `loadCurrentState`](src/orders/retry.ts)을 확인했다.
```

문서 순서나 앞선 인용이 바뀌면 후속 번호도 다시 계산한다. 같은 `cite-` 키는 모든 문서에서 같은 번호를 사용한다. 중앙 근거 문서는 인용된 항목만 포함하고 문서 묶음의 마지막 탐색 항목으로 연결한다.

## 출처 locator

- 저장소 파일은 로컬 절대 경로 대신 문서 위치에서 해석되는 저장소 상대 링크를 사용한다.
- 파일 전체보다 symbol이 주장을 더 정확히 가리키면 링크명이나 설명에 symbol을 쓴다.
- 줄 번호는 정확한 위치가 필요할 때만 사용하고 코드가 바뀌면 의미가 달라질 수 있으므로 revision을 함께 기록한다.
- 외부 자료는 공식·1차 출처의 제목과 링크, 적용 버전이나 확인 날짜 중 판단에 필요한 정보만 기록한다.
- `reverse-engineer-service`의 `RE-001` 같은 claim ID는 필요한 경우 근거 항목의 추적 정보로 연결할 수 있지만 표시 번호나 `cite-` 키를 대신하지 않는다.
- 비밀값, 개인정보, 실제 업무 데이터와 로컬 사용자 경로는 근거 항목에 복사하지 않는다.

## 기존 renderer

Pandoc와 Quarto에서는 프로젝트가 쓰는 bibliography와 `[@key]` 형식을 유지하고 숫자 CSL 스타일로 렌더링한다. LaTeX에서는 기존 BibLaTeX 또는 natbib 설정을 유지한다. 장별 파일을 합쳐 하나의 산출물을 만들 때는 renderer가 합본 순서에서 전역 번호를 계산하게 하고 해당 빌드를 실행해 결과를 확인한다.

새 인용 형식을 기존 renderer 위에 중복으로 만들지 않는다. renderer가 개별 페이지와 합본의 번호를 다르게 처리하면 사용자가 실제로 읽는 산출물을 기준으로 번호 범위를 정하고 그 결정을 문서 작업 결과에 기록한다.

## 검사

기본 Markdown 형식은 Python 표준 라이브러리 검사기로 확인한다.

```text
python scripts/validate-citations.py docs/guide.md
python scripts/validate-citations.py --registry docs/references.md docs/chapter-1.md docs/chapter-2.md
```

전역 모드의 문서 인자는 실제 읽기 순서로 전달한다. 검사는 다음을 확인한다.

- 키의 최초 등장순과 `1`부터 시작하는 연속 번호
- 같은 키의 번호 재사용과 서로 다른 키의 번호 중복
- 누락, 중복 또는 미사용 근거 항목
- 로컬 또는 중앙 근거 문서로 향하는 링크 대상
- 근거 항목에 포함된 대표적인 Windows, POSIX 또는 사용자 홈 절대 경로

검사기는 fenced code, inline code와 HTML 주석의 예시 및 `cite-`가 아닌 일반 링크와 각주를 무시한다. Python이 없으면 같은 항목을 수동으로 확인하고 새 패키지를 자동 설치하지 않는다.
