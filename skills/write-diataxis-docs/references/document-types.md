# 문서 유형 가이드

문서 계약과 실제 문장에 같은 분류 기준을 적용한다. 유형 이름보다 독자의 현재 필요를 우선한다.

## 유형 선택

| 유형 | 독자의 상태 | 중심 질문 | 범위를 결정하는 것 |
| --- | --- | --- | --- |
| 튜토리얼 | 능력을 습득하는 중 | 처음 성공하려면 무엇을 경험해야 하는가 | 검증된 학습 경로 |
| 방법 안내서 | 능력을 실제 일에 적용하는 중 | 이 상황에서 목표를 어떻게 달성하는가 | 사용자의 현실적 과업 |
| 참조 | 작업 중 정확한 사실을 조회함 | 무엇이며 어떤 조건으로 동작하는가 | 제품과 시스템의 구조 |
| 설명 | 경험과 사실을 연결해 이해함 | 왜 이렇고 무엇과 연결되는가 | 하나의 경계가 있는 주제나 왜 질문 |

판단이 어려우면 다음을 확인한다.

- 사용자가 그대로 따라 하는 학습 경험이 필요한가, 실제 작업의 해법이 필요한가?
- 지금 일을 멈추지 않고 사실을 찾아야 하는가, 일에서 물러나 관계와 이유를 이해하려는가?
- 문서가 책임질 성공은 능력 획득인가, 과업 완료인가, 정확한 조회인가, 정신모형 형성인가?

## 독자 프로필 적용

Diátaxis 유형은 독자가 어떤 도움을 필요로 하는지 결정하고, 독자 프로필은 그 도움의 깊이, 언어, 순서와 형식을 조정한다. 같은 유형이라도 다음을 독자에 맞춘다.

- 튜토리얼: 생략하지 않을 기본 동작, 안전한 경로의 크기, 예상 결과를 확인하는 방식
- 방법 안내서: 전제로 둘 숙련도, 현실적 분기, 권한·위험과 완료 조건의 상세도
- 참조: 독자가 사용하는 용어와 조회 경로, 필수 필드의 설명 밀도와 예제 범위
- 설명: 출발할 정신모형, 먼저 다룰 왜 질문, 사례·반례와 트레이드오프의 깊이

직함만으로 초보자나 전문가라고 단정하지 않는다. 도메인, 제품·시스템, 도구·절차 지식은 서로 다를 수 있으므로 문서에 필요한 축만 별도로 판단한다. 독자 취향 때문에 선택한 유형의 책임을 바꾸지 않는다.

## 튜토리얼

- 완성할 구체적인 결과와 검증된 환경을 먼저 제시한다.
- 가능한 한 일찍 눈에 보이는 작은 성공을 만든다.
- 하나의 안전하고 반복 가능한 경로만 제공한다.
- 각 단계에 행동, 예상 결과, 관찰 지점과 회복 방법을 가깝게 둔다.
- 기본 동작도 생략하지 말고 학습자가 판단해야 할 선택지를 제거한다.
- 긴 원리, 전체 옵션 목록과 운영 환경의 분기는 링크된 설명·참조·방법 안내서로 옮긴다.

튜토리얼이 약해지는 신호는 설명이 행동보다 길거나, 여러 도구 중 하나를 고르게 하거나, 결과를 확인하지 않은 채 다음 단계로 넘어가는 것이다.

## 방법 안내서

- 제목과 도입을 제품 기능이 아니라 사용자가 달성할 결과로 쓴다.
- 적용 상황, 전제조건, 권한, 위험과 완료 조건을 명시한다.
- 실제 환경에서 생길 수 있는 핵심 분기와 되돌릴 수 없는 지점을 다룬다.
- 독자가 기본 도구와 용어를 안다고 가정하고 필요한 절차에 집중한다.
- 선택지는 목표 달성에 영향을 주는 조건과 함께 제시한다.
- 개념 교육과 모든 설정값의 나열은 설명과 참조로 연결한다.

방법 안내서가 약해지는 신호는 메뉴나 API 이름이 문서의 목적이 되거나, 이상적인 성공 경로만 있고 실패 시 판단 기준이 없는 것이다.

## 참조

- 제품의 API, 명령, 설정, 스키마, 상태나 권한 구조에 맞춰 정보를 배열한다.
- 같은 종류의 항목은 같은 필드와 순서로 기술한다.
- 유형, 필수 여부, 기본값, 제약, 오류, 버전과 지원 범위를 빠뜨리지 않는다.
- 사실을 간결하고 중립적으로 기술하며 권장 절차나 긴 배경 설명은 링크한다.
- 코드나 스키마에서 생성할 수 있는 정보는 실제 원천과 동기화되도록 검증한다.

참조가 약해지는 신호는 특정 목표의 단계가 본문을 지배하거나, 일부 항목만 장황하게 설명해 조회 위치를 예측할 수 없는 것이다.

## 설명

- 하나의 실제 또는 가상의 `왜` 질문으로 범위를 고정한다.
- 개념 사이의 관계, 배경, 설계 제약과 결과를 연결한다.
- 구체적인 사례와 반례를 원리와 대응시킨다.
- 대안, 트레이드오프, 경계 사례와 설계상 함의를 다룬다.
- 독자가 이미 접한 행동과 사실을 더 안정된 정신모형으로 묶는다.
- 실행을 위해 따라 해야 할 긴 절차와 전체 명세는 다른 문서로 옮긴다.

설명이 약해지는 신호는 범위가 끝없이 넓어지거나, 의견을 사실처럼 쓰거나, 명령 모음이 논지를 대신하는 것이다.

## 혼합과 분리

한 문서 안의 짧은 교차 유형 내용은 현재 흐름을 유지하는 데 필요한 만큼 허용한다. 다음 조건에서는 분리를 우선한다.

- 서로 다른 독자나 사용 순간을 전제로 한다.
- 한 부분을 읽는 동안 다른 부분이 작업이나 학습 흐름을 중단한다.
- 독립된 제목과 탐색 경로가 있어야 다시 찾을 수 있다.
- 별도로 검증하거나 갱신해야 하는 생명주기를 가진다.
- 주 독자와 부 독자의 사용 순간, 결과, 책임이나 사전 지식이 달라 같은 흐름으로 해결할 수 없다.

분리할 때 현재 문서의 문맥을 잃지 않도록 한두 문장의 요약과 구체적인 링크를 남긴다. 새 정보 구조를 한 번에 설계하지 말고 문제가 확인된 문서부터 점진적으로 정리한다.

## 선택적 숙련 부가층

튜토리얼이나 명시적 요청에서만 다음 순서 중 필요한 단계를 사용한다.

1. 완성 예제를 관찰하고 그대로 재현한다.
2. 일부 안내만 있는 작업을 완성한다.
3. 조건이 달라진 사례에 같은 판단 기준을 적용한다.
4. 자료 없이 독립적으로 수행한다.
5. 선택의 이유와 위험한 대안을 설명한다.

연습은 문서의 주된 목적을 대신하지 않아야 한다. 정상 상태, 흔한 실패 상태와 위험한 오판 상태를 구별하게 하고, 사용자가 능력을 얻을수록 힌트를 줄인다.
