# 독자 모델링 가이드

독자 프로필은 문서를 읽는 개인의 가상 전기가 아니라, 여러 문서에서 반복해서 사용할 역할 기반 맥락이다. 이번 문서에만 적용되는 조건은 프로필과 분리한다.

## 정보의 세 층

| 층 | 다루는 내용 | 저장 위치 |
| --- | --- | --- |
| 요청자 | 전달 의도, 포함·제외 요구, 일정과 형식 제약 | 작업 메모 |
| 독자 프로필 | 역할, 반복 과업, 지식, 질문, 환경과 접근성 제약 | 기존 관례 또는 `docs/audiences/<role-slug>.md` |
| 문서 계약 | 주 독자, 사용 순간, 한 가지 필요, 기대 결과, 유형 | 대상 문서 계획이나 작업 메모 |

발표 시간, 특정 배포 revision, 이번 검토 범위처럼 빨리 변하는 조건은 프로필에 넣지 않는다. 요청자의 설득 목적과 독자의 이해·안전이 충돌하면 맞춤화를 설득 조작에 사용하지 말고 충돌을 드러낸다.

## 탐색과 선택

1. 사용자가 지정한 프로필이나 독자 정보를 우선한다.
2. 대상 프로젝트에서 audience, reader, persona, user research 관례를 찾고 명시적으로 연결된 자료를 읽는다.
3. 별도 관례가 없으면 `docs/audiences/`를 확인한다. 이름만 비슷한 프로필을 자동 적용하지 말고 역할, 사용 순간과 과업이 맞는지 대조한다.
4. 적합한 프로필이 없으면 요청, 기존 문서, 역할·권한 정의와 제품 용어에서 이번 작업용 가설을 만든다.
5. 결과의 범위, 안전성이나 문서 유형을 바꿀 미확인 사항만 질문한다. 나머지는 상태가 표시된 가정으로 진행한다.

주 독자를 한 명 또는 하나의 역할 집단으로 고정한다. 부 독자는 같은 필요와 흐름을 공유할 때만 포함한다. 다음 중 하나라도 다르면 별도 문서나 별도 진입점을 우선한다.

- 사용 순간과 달성하려는 결과
- 결정·실행 책임과 위험
- 필요한 사전 지식과 생략 가능한 기본 절차
- 사용하는 환경, 채널 또는 접근성 지원

## 프로필 내용

프로젝트 관례가 없으면 사람이 읽고 검토하기 쉬운 Markdown 제목과 절을 사용한다. 빈 항목을 채우기 위해 정보를 만들지 말고, 작성 결정을 바꾸는 항목만 포함한다.

- 역할, 책임, 결정·실행 권한
- 반복되는 사용 순간과 달성하려는 결과
- 도메인, 제품·시스템, 도구·절차별 지식
- 용어 친숙도, 현재 정신모형과 예상되는 오해
- 먼저 답해야 할 질문, 우려와 잘못 판단했을 때의 위험
- 시간, 실행 환경, 전달 채널, 접근성과 지원 제약
- 위 정보에서 도출한 어휘, 정보 순서, 설명 깊이, 예시와 형식 전략

독자에 관한 각 핵심 주장은 다음 상태와 함께 관리한다.

| 상태 | 의미 | 처리 |
| --- | --- | --- |
| `확인` | 인터뷰, 관찰, 집계된 사용 데이터, 승인된 역할 정의나 독자의 명시적 진술로 뒷받침됨 | 적용 범위와 가능한 출처를 기록한다. |
| `추론` | 확인된 역할이나 행동에서 도출했지만 독자에게 직접 검증하지 않음 | 작성 전략을 보수적으로 조정하고 검증 필요성을 남긴다. |
| `미확인` | 문서 결과에 영향을 주지만 자료가 없음 | 질문하거나 문서별 가정으로 밝힌다. |

프로필에는 실제로 내용을 검토한 날짜와 근거가 적용되는 제품·조직 범위를 가능한 만큼 기록한다. 검토일을 근거의 작성일에서 추정하거나 임의의 날짜로 채우지 않는다. 원시 인터뷰, 로그, 개인 분석 데이터는 링크 가능한 안전한 집계 자료로 대체한다.

## 안전과 최소 수집

- 이름, 사진, 가상 전기와 장식적인 나이·성별·지역·성격을 넣지 않는다.
- 개인정보와 민감한 특성은 저장하지 않는다. 접근성이나 지원에 직접 필요한 특성은 승인된 집계 수준의 필요와 장벽으로만 표현한다.
- 직함만으로 지식, 태도나 표현 취향을 단정하지 않는다.
- 변화에 대한 우려나 감정은 관찰 근거가 있을 때만 기록하고, 독자의 판단을 우회하는 표현 전략으로 바꾸지 않는다.
- 선호 형식은 접근성과 목적 달성에 도움이 되는 범위에서만 적용한다. 요약 선호를 이유로 필수 위험, 전제나 설명을 제거하지 않는다.

## 저장과 갱신

문서 작성 중 만든 임시 가설은 자동으로 파일에 저장하지 않는다. 여러 문서에서 같은 역할이 반복되거나 팀이 검토할 공통 기준이 될 때 저장을 제안하고, 사용자가 승인하거나 명시적으로 요청한 경우에만 새 프로필을 만든다.

기존 프로필은 한 번의 문서 작업에서 조용히 고치지 않는다. 현재 요청이나 새 근거와 충돌하면 다음 순서로 처리한다.

1. 충돌하는 주장, 상태, 출처와 검토일을 확인한다.
2. 이번 문서에는 더 직접적이고 현재 범위에 맞는 정보를 문서별 조건으로 사용한다.
3. 기존 프로필의 영향과 가장 작은 갱신 후보를 보고한다.
4. 갱신 요청이나 승인을 받으면 기존 인간 서술과 출처를 보존하며 필요한 항목만 수정한다.

## 문서에 적용

프로필을 본문에 그대로 복사하지 말고 작성 결정으로 변환한다.

| 독자 정보 | 문서 결정 |
| --- | --- |
| 먼저 가진 질문과 사용 순간 | 제목, 도입과 정보 순서 |
| 지식과 용어 친숙도 | 전제조건, 용어 설명과 생략 가능한 기본 단계 |
| 책임과 결정 권한 | 행동 주체, 선택지, 승인·완료 조건 |
| 환경과 채널 | 명령, 화면 설명, 예제 형식과 탐색 구조 |
| 위험과 예상 오해 | 경고 위치, 반례, 실패 확인과 회복 방법 |
| 접근성과 지원 필요 | 대체 표현, 구조, 감각에 의존하지 않는 확인 방법 |

검토에서는 기술적으로 정확한지만 보지 말고, 선택한 독자가 시작점을 찾고 용어를 해석하며 필요한 행동·조회·이해를 완료할 수 있는지 확인한다. 실제 독자 테스트나 사용 데이터가 없으면 이를 프로필 기반 적합성 판단으로 한정한다.
