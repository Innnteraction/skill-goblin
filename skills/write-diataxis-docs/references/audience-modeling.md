# 독자 모델링 가이드

독자 프로필은 문서를 읽는 개인의 가상 전기가 아니라, 여러 문서에서 반복해서 사용할 역할 기반 맥락이다. 이번 문서에만 적용되는 조건과 목표 개념별 지식 상태는 프로필과 분리한다.

## 운영 모델

독자 맞춤 문서는 다음 네 단계를 거친다.

1. **재사용 가능한 독자 프로필**에서 역할, 반복 과업, 권한, 환경과 공통 기반을 가져온다.
2. **문서별 독자 상태**에서 이번 결과에 필요한 목표 지식과 현재 지식의 격차를 확인한다.
3. **변환 전략**에서 포함할 내용, 순서, 표현, 안내 강도와 후속 탐색을 결정한다.
4. **검증**에서 각 독자 정보가 작성 결정으로 이어졌는지, 독자가 결과를 확인하거나 새 사례에 전이할 수 있는지 점검한다.

독자 모델은 관찰과 가정을 기록하고, 변환 전략은 그 모델을 문서에 적용한다. 둘을 분리해야 프로필의 정보가 장식으로 남거나 한 문서의 일시적 조건이 영구 특성으로 굳는 것을 막을 수 있다.

## 정보의 층

| 층 | 다루는 내용 | 저장 위치 |
| --- | --- | --- |
| 요청자 | 전달 의도, 포함·제외 요구, 일정과 형식 제약 | 작업 메모 |
| 독자 프로필 | 역할, 반복 과업, 공통 기반, 반복되는 지식·오해, 환경과 접근성 제약 | 기존 관례 또는 `docs/audiences/<role-slug>.md` |
| 문서별 독자 상태 | 목표 개념별 지식 상태, 이번 질문과 개념 연결 | 대상 문서 계획이나 작업 메모 |
| 문서 계약 | 주 독자, 사용 순간, 한 가지 필요, 기대 결과, 유형과 적응 결정 | 대상 문서 계획이나 작업 메모 |

발표 시간, 특정 배포 revision, 이번 검토 범위처럼 빨리 변하는 조건은 프로필에 넣지 않는다. 요청자의 설득 목적과 독자의 이해·안전이 충돌하면 맞춤화를 설득 조작에 사용하지 말고 충돌을 드러낸다.

## 탐색과 선택

1. 사용자가 지정한 프로필이나 독자 정보를 우선한다.
2. 대상 프로젝트에서 audience, reader, persona, user research 관례를 찾고 명시적으로 연결된 자료를 읽는다.
3. 별도 관례가 없으면 `docs/audiences/`를 확인한다. 이름만 비슷한 프로필을 자동 적용하지 말고 역할, 사용 순간과 과업이 맞는지 대조한다.
4. 적합한 프로필이 없으면 요청, 기존 문서, 역할·권한 정의와 제품 용어에서 이번 작업용 가설을 만든다.
5. 결과의 범위, 안전성이나 문서 유형을 바꿀 미확인 사항만 질문한다. 나머지는 상태가 표시된 가정으로 진행한다.

주 독자를 한 명 또는 하나의 역할 집단으로 고정한다. 부 독자는 같은 필요와 흐름을 공유할 때만 포함한다. 다음 중 하나라도 다르면 별도 문서나 별도 진입점을 우선한다.

- 사용 순간과 달성하려는 결과
- 결정·실행 책임과 위험
- 필요한 사전 지식과 생략 가능한 기본 절차
- 사용하는 환경, 채널 또는 접근성 지원

## 프로필 내용

프로젝트 관례가 없으면 [독자 프로필 템플릿](../assets/audience-profile-template.md)을 참고해 사람이 읽고 검토하기 쉬운 Markdown 제목과 절을 사용한다. 빈 항목을 채우기 위해 정보를 만들지 말고, 작성 결정을 바꾸는 항목만 포함한다.

- 역할, 책임, 결정·실행 권한
- 반복되는 사용 순간과 달성하려는 결과
- 공통 기반으로 확인된 업무 용어, 개념, 도구, 산출물, 작업 흐름과 경험
- 반복해서 적용할 가치가 있는 도메인, 제품·시스템, 도구·절차별 지식과 오해
- 먼저 답해야 할 질문, 우려와 잘못 판단했을 때의 위험
- 시간, 실행 환경, 전달 채널, 접근성과 지원 제약
- 위 정보에서 도출한 어휘, 정보 순서, 설명 깊이, 예시와 형식 전략

`초급`, `중급`, `고급` 같은 단일 등급은 사용하지 않는다. 같은 역할도 도메인에는 익숙하지만 제품은 처음이거나, 도구 사용에는 능숙하지만 절차의 위험을 모를 수 있다. 지식은 문서에 필요한 축별로 기록한다.

### 공통 기반

공통 기반은 작성자와 독자가 함께 안다고 근거를 갖고 취급할 수 있는 자원이다. 다음 항목 중 새 개념을 설명하거나 탐색 경로를 정하는 데 실제로 쓸 것만 기록한다.

- 독자가 뜻과 사용 맥락을 아는 업무 용어와 공식 용어
- 이미 사용하는 제품, 도구, 화면, 명령과 산출물
- 반복해서 수행하는 작업 흐름과 판단 경험
- 현재 정신모형에서 안정적으로 이해한 관계와 규칙

직함이나 조직 소속만으로 공통 기반을 추정하지 않고, 한 번의 발언을 그 적용 범위 너머로 일반화하지 않는다. 개인의 고유한 말투나 문장을 모방 대상으로 저장하지 않고, 독자가 명시적으로 제공했거나 안전하게 집계된 업무 용어와 익숙한 표현 구조만 사용한다.

## 문서별 독자 상태

이번 문서의 목표 결과를 내는 데 필요한 개념과 동작을 나열하고, 독자의 현재 상태를 다음처럼 구분한다.

| 상태 | 의미 | 작성 처리 |
| --- | --- | --- |
| `알고 있음` | 이번 과업에서 독립적으로 적용할 수 있음 | 반복 설명을 줄이고 필요한 지점으로 바로 연결한다. |
| `부분 이해` | 일부 사실이나 절차는 알지만 관계·경계·이유가 불안정함 | 빠진 연결과 판별 기준을 보충한다. |
| `오해` | 결과나 안전을 해치는 잘못된 정신모형이 있음 | 오해가 실패하는 반례를 보인 뒤 정확한 모델과 구별 기준을 제시한다. |
| `모름` | 목표 개념을 해석하거나 적용할 기반이 없음 | 필요한 선수 지식과 안내를 제공하거나 선행 문서로 연결한다. |

각 상태에도 `확인`, `추론`, `미확인` 근거 상태를 붙인다. 자료가 없으면 역할 프로필의 영구 지식으로 저장하지 않고 이번 문서의 가정으로만 둔다. 역할, 목표와 책임이 같더라도 목표 개념의 지식 상태가 크게 다르면 설명 깊이가 다른 진입점이나 문서로 분리한다.

## 개념 연결

독자의 현재 정신모형만으로 목표 개념을 이해하기 어려울 때만 익숙한 경험과 목표 개념을 연결한다. 단순히 닮은 사물을 제시하지 말고 관계를 대응시킨다.

| 항목 | 질문 |
| --- | --- |
| 원천 | 독자가 근거를 갖고 아는 개념·도구·작업 경험은 무엇인가? |
| 목표 | 새로 이해해야 할 개념과 관계는 무엇인가? |
| 대응 | 원천의 어떤 요소와 관계가 목표의 무엇에 대응하는가? |
| 한계 | 어디부터 대응하지 않으며 그대로 적용하면 어떤 오해가 생기는가? |
| 전이 확인 | 새로운 사례에서 독자가 관계를 적용하거나 결과를 설명할 수 있는가? |

필요할 때 다음 순서로 설명한다.

1. 독자의 현재 질문과 익숙한 경험을 짧게 활성화한다.
2. 경험 속 요소보다 관계를 목표 개념의 관계에 대응시킨다.
3. 비유 표현에 머물지 않고 공식 용어와 정확한 모델을 도입한다.
4. 대응이 깨지는 경계와 예상되는 오해를 반례로 구분한다.
5. 다른 사례에 적용하거나 예상 결과를 설명하게 해 이해 전이를 확인한다.

개념 연결이 정확한 설명을 대체하지 않게 한다. 안전·보안·법적 판단처럼 잘못된 전이가 큰 피해를 낼 수 있으면 검증된 공식 모델과 판별 기준을 먼저 제공하고, 비유는 보조 설명으로만 사용한다.

독자에 관한 각 핵심 주장은 다음 상태와 함께 관리한다.

| 상태 | 의미 | 처리 |
| --- | --- | --- |
| `확인` | 인터뷰, 관찰, 집계된 사용 데이터, 승인된 역할 정의나 독자의 명시적 진술로 뒷받침됨 | 적용 범위와 가능한 출처를 기록한다. |
| `추론` | 확인된 역할이나 행동에서 도출했지만 독자에게 직접 검증하지 않음 | 작성 전략을 보수적으로 조정하고 검증 필요성을 남긴다. |
| `미확인` | 문서 결과에 영향을 주지만 자료가 없음 | 질문하거나 문서별 가정으로 밝힌다. |

프로필에는 실제로 내용을 검토한 날짜, 근거가 적용되는 제품·조직 범위, 프로필을 다시 검토해야 할 무효화 조건과 미확인 질문을 가능한 만큼 기록한다. 제품, 역할, 권한이나 반복 업무 흐름이 바뀌거나 실제 독자 결과가 프로필과 충돌하면 갱신 후보로 표시한다. 검토일을 근거의 작성일에서 추정하거나 임의의 날짜로 채우지 않는다. 원시 인터뷰, 로그, 개인 분석 데이터는 링크 가능한 안전한 집계 자료로 대체한다.

## 안전과 최소 수집

- 이름, 사진, 가상 전기와 장식적인 나이·성별·지역·성격을 넣지 않는다.
- 개인정보와 민감한 특성은 저장하지 않는다. 접근성이나 지원에 직접 필요한 특성은 승인된 집계 수준의 필요와 장벽으로만 표현한다.
- 원시 대화, 개인 행동 로그와 개인별 어휘·문장 모음을 저장하지 않는다.
- 직함만으로 지식, 태도나 표현 취향을 단정하지 않는다.
- 변화에 대한 우려나 감정은 관찰 근거가 있을 때만 기록하고, 독자의 판단을 우회하는 표현 전략으로 바꾸지 않는다.
- 선호 형식은 접근성과 목적 달성에 도움이 되는 범위에서만 적용한다. 요약 선호를 이유로 필수 위험, 전제나 설명을 제거하지 않는다.

## 저장과 갱신

문서 작성 중 만든 임시 가설은 자동으로 파일에 저장하지 않는다. 여러 문서에서 같은 역할이 반복되거나 팀이 검토할 공통 기준이 될 때 저장을 제안하고, 사용자가 승인하거나 명시적으로 요청한 경우에만 새 프로필을 만든다.

기존 프로필은 한 번의 문서 작업에서 조용히 고치지 않는다. 현재 요청이나 새 근거와 충돌하면 다음 순서로 처리한다.

1. 충돌하는 주장, 상태, 출처와 검토일을 확인한다.
2. 이번 문서에는 더 직접적이고 현재 범위에 맞는 정보를 문서별 조건으로 사용한다.
3. 기존 프로필의 영향과 가장 작은 갱신 후보를 보고한다.
4. 갱신 요청이나 승인을 받으면 기존 인간 서술과 출처를 보존하며 필요한 항목만 수정한다.

## 문서에 적용

프로필을 본문에 그대로 복사하지 말고 작성 결정으로 변환한다.

| 독자 정보 | 문서 결정 |
| --- | --- |
| 먼저 가진 질문과 사용 순간 | 제목, 도입과 정보 순서 |
| 공통 기반과 목표별 지식 상태 | 전제조건, 개념 연결, 공식 용어 도입 시점과 생략 가능한 기본 단계 |
| 책임과 결정 권한 | 행동 주체, 선택지, 승인·완료 조건 |
| 환경과 채널 | 명령, 화면 설명, 예제 형식과 탐색 구조 |
| 위험과 예상 오해 | 경고 위치, 반례, 실패 확인과 회복 방법 |
| 접근성과 지원 필요 | 대체 표현, 구조, 감각에 의존하지 않는 확인 방법 |

맞춤화 결정은 다음 다섯 범주로 정리한다.

- **내용 선택**: 포함할 선수 지식, 생략할 중복, 보존할 위험과 전제
- **정보 순서**: 먼저 가진 질문, 익숙한 출발점, 공식 모델과 세부 사항의 배치
- **표현과 예시**: 사용할 업무 용어, 개념 연결, 사례·반례와 대체 표현
- **안내 강도**: 단계별 안내, 힌트, 확인 지점과 독립 수행 범위
- **후속 탐색**: 다음 문서, 심화 설명, 참조 항목과 되돌아올 위치

취향이나 지식 상태를 이유로 정확성, 안전성, 필수 전제와 필요한 인지 활동을 제거하지 않는다. 초보자에게 필요한 안내가 숙련자에게 중복이 될 수 있으므로 주제별 지식 상태가 확인된 경우에만 안내 강도를 줄인다.

## 검증

프로필의 각 핵심 정보가 내용·순서·표현·안내·탐색 결정 중 하나 이상으로 이어지는지 확인한다. 아무 결정도 바꾸지 않는 정보는 프로필에서 제거하거나 근거 메모로 옮긴다.

문서 유형에 맞춰 성공을 확인한다.

| 유형 | 독자 확인 |
| --- | --- |
| 튜토리얼 | 안내를 따라 결과를 만들고 변형 과제를 독립적으로 수행하는가? |
| 방법 안내서 | 실제 조건에서 과업을 완료하고 성공·실패·회복을 판별하는가? |
| 참조 | 필요한 항목을 찾고 값을 정확히 해석하는가? |
| 설명 | 관계와 경계를 설명하고 새로운 사례에 적용하는가? |

기술적으로 정확한지만 보지 말고, 선택한 독자가 시작점을 찾고 용어를 해석하며 필요한 행동·조회·이해를 완료할 수 있는지 확인한다. 실제 독자 테스트나 사용 데이터가 없으면 `이해도 검증 완료`가 아니라 `프로필 기반 적합성 검토 완료`로 보고한다.
